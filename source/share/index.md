## Codex 上手笔记：让 AI 直接改你的代码库

> 一句话总结：它不只是在聊天框里给你一段代码，而是能自己读你的项目、改文件、跑测试、提 PR。

### 它到底是什么

Codex 是 OpenAI 做的编程 Agent。和普通的 AI 聊天不同的是，它拿到的是一个**真实的代码仓库**，可以：

- 读整个项目的结构和文件
- 直接修改文件
- 执行命令、跑测试
- 把改动整理成一次提交或一个 Pull Request

你描述一个任务，它自己去干活，干完给你看 diff。

### 三种用法

**1. 命令行（最常用）**

在项目根目录启动，用自然语言描述需求，比如「把首页的卡片改成毛玻璃样式」或者「修一下这个测试为什么挂」。它在沙箱里执行，跑完把改动交给你审。

**2. IDE 插件**

在编辑器里选中一段代码，直接让它改、让它解释、让它补测试。适合改一个小函数这种轻量场景。

**3. 云端任务**

把任务丢给云端，它在隔离环境里跑，跑完给你一个 PR 链接。适合「睡前丢一个任务，早上起来看结果」。

### 实际用起来的感觉

**好用在哪：**

- **上下文完整**。它会自己去读相关文件，不需要你复制粘贴一大堆代码。
- **会验证**。改完会尝试跑测试，跑挂了会自己再改一轮。
- **过程可见**。每一步执行了什么命令、改了哪些文件，都能看到。

**要注意的：**

- **别让它一次干太大的事**。「重构整个项目」这种任务它大概率会跑偏，拆成小任务效果更好。
- **一定要看 diff**。它会写出能跑但不符合你项目风格的代码，review 不能省。
- **测试是底线**。项目有测试的话，它的产出质量会明显高一个档。
- **敏感操作别放权**。删除文件、改配置、动数据库这类，最好自己确认。

### 适合什么场景

| 场景 | 合适度 |
|---|---|
| 修 bug、补测试 | ⭐⭐⭐⭐⭐ |
| 写重复性的样板代码 | ⭐⭐⭐⭐⭐ |
| 小范围重构 | ⭐⭐⭐⭐ |
| 从零搭一个新项目 | ⭐⭐⭐ |
| 大型架构改造 | ⭐⭐ |

### 我的用法

现在我的习惯是：**先自己把问题想清楚，再用它执行**。

把它当成一个手很快、但需要你盯着的新同事——你负责判断方向，它负责敲键盘。这样效率最高，也最不容易翻车。

> 工具会一直变，但这套「想清楚 → 拆小 → 验收」的节奏不会过时。
